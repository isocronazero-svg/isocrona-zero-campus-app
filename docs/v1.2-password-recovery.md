# V1.2 · Recuperación de contraseña

Implementación asociada a #316.

## Flujo de usuario

1. En el login aparece `¿Has olvidado tu contraseña?`.
2. El usuario introduce su correo.
3. La respuesta pública siempre es neutra y no confirma si existe una cuenta.
4. Si la cuenta existe, se envía un enlace de un solo uso.
5. El enlace caduca a los 30 minutos.
6. El usuario crea una contraseña nueva y vuelve al login.

## Seguridad

- Nunca se envía ni almacena la contraseña actual en texto claro.
- Los tokens se generan con 32 bytes aleatorios y se persisten únicamente como SHA-256.
- Los tokens viven en una tabla privada de SQLite, fuera de `/api/state` y del snapshot JSON del portal.
- Un segundo reset invalida los enlaces anteriores del mismo correo.
- Un token usado o caducado no puede reutilizarse.
- Hay límites por IP y por hash de correo.
- El cambio de contraseña invalida las sesiones anteriores normales, `Recordarme` y JWT emitidos antes del cambio.
- Auditoría registra solicitud/completado sin token ni contraseña.

## Compatibilidad

- Cuentas legacy del estado local.
- Cuentas PostgreSQL cuando `DATABASE_URL` está habilitado.
- Reutiliza el proveedor de correo configurado actualmente.
- QA puede usar `IZ_PASSWORD_RESET_TEST_OUTBOX` para capturar correos sintéticos sin enviar mensajes reales.

## Integración técnica

La funcionalidad se instala antes del arranque de `server.js` mediante `server-entry.js`. El bootstrap añade únicamente las rutas públicas de recuperación y la invalidación de sesiones necesaria, manteniendo el servidor principal sin cambios en este incremento.

Rutas:

- `POST /api/password-recovery/request`
- `GET /api/password-recovery/validate?token=...`
- `POST /api/password-recovery/reset`

El navegador carga `public/password-recovery.js` desde el `app.js` servido por el bootstrap.

## QA automatizada

`scripts/check-password-recovery.mjs` comprueba:

- respuesta neutra para correo existente/inexistente;
- envío sintético;
- token válido, superseded, usado y caducado;
- hash persistido y ausencia del token en `state.json`;
- cambio real de contraseña;
- rechazo de la contraseña anterior;
- invalidación de sesión normal y `Recordarme`;
- carga de la UI de recuperación.
