# V1.1 · Runbook de QA

## Entorno

- Proyecto Railway: `isocrona-zero-v1-1-qa`
- Entorno: `qa`
- Servicio: `portal-v1-1-qa`
- URL técnica: `https://portal-v1-1-qa-qa.up.railway.app`
- Rama: `feature/v1.1`
- Datos: volumen persistente exclusivo de QA. No usar ni copiar datos de producción.
- Correo: desactivado en QA.

> No usar contraseñas reales de administradores o socios en este entorno. Antes de compartir la URL fuera de la junta, proteger el acceso o sustituir las credenciales demo por cuentas QA temporales.

## Gate 0 · Salud

- [ ] `/healthz` responde correctamente.
- [ ] Railway muestra 1 réplica online y 0 críticos.
- [ ] SHA desplegado coincide con el HEAD validado de `feature/v1.1`.
- [ ] Producción `portal.isocronazero.org` continúa en `main` y sin cambios.

## Gate 1 · Identidad de administradores (#295)

Usar dos navegadores/perfiles separados y dos cuentas admin QA diferentes.

- [ ] Admin A inicia sesión y aparece siempre en su propio perfil.
- [ ] Admin B inicia sesión y aparece siempre en su propio perfil.
- [ ] La cabecera muestra `Trabajando como: ...`.
- [ ] Admin A cambia a Socio 1 y la cabecera pasa a `Estás gestionando a: ...`.
- [ ] Admin B cambia a Socio 2 y no cambia el contexto de Admin A.
- [ ] Recargar ambas sesiones conserva únicamente el contexto de cada navegador.
- [ ] Cerrar sesión y volver a entrar devuelve al perfil propio.
- [ ] `Volver a mi perfil` funciona.

## Gate 2 · Precios y reservas

- [ ] Curso con precio socio y no socio diferentes.
- [ ] Socio ve/aplica el precio de socio.
- [ ] No socio ve/aplica el precio general.
- [ ] Caso socio gratis (0 €) no cae al precio general.
- [ ] Reserva administrativa guarda el precio correcto.
- [ ] Editar el precio del curso no altera el precio ya aplicado a una inscripción anterior.

## Gate 3 · Justificante → Tesorería → ingreso (#294, #297, #298)

- [ ] Tesorería pulsa `Solicitar justificante`.
- [ ] El socio recibe un aviso privado visible.
- [ ] El aviso incluye el curso y CTA `Adjuntar justificante`.
- [ ] Repetir la solicitud no duplica avisos.
- [ ] El socio adjunta PDF o imagen.
- [ ] Tesorería puede verlo dentro del portal sin descargarlo.
- [ ] `Justificante adjunto` sigue siendo distinto de `Pago validado`.
- [ ] Marcar incidencia guarda la nota y no crea ingreso.
- [ ] Validar pago registra quién y cuándo.
- [ ] Tras validar, el importe aparece una sola vez en `Ingresos`.
- [ ] El desglose cuota / curso / jornada es correcto.
- [ ] Exportación CSV abre correctamente y no duplica movimientos.

## Gate 4 · Cuota de altas octubre-diciembre (#296)

- [ ] Alta 30/09/2026 → cuota 2026.
- [ ] Alta 01/10/2026 → cuota 2027.
- [ ] Alta en noviembre 2026 → ficha muestra `Cuota correspondiente a 2027`.
- [ ] Alta 31/12/2026 → cuota 2027.
- [ ] Alta 01/01/2027 → cuota 2027.
- [ ] Fecha real de alta no se modifica.
- [ ] Corrección administrativa excepcional cambia solo el año de cuota y queda auditada.

## Gate 5 · WhatsApp (#293)

- [ ] Administración configura un enlace oficial de WhatsApp.
- [ ] URL no oficial es rechazada.
- [ ] Socio activo ve `Unirme al canal de WhatsApp`.
- [ ] Usuario no socio/no autenticado no recibe el enlace privado.
- [ ] El enlace abre WhatsApp o navegador correctamente en móvil.

## Gate 6 · Diplomas y auditoría

- [ ] Previsualización usa los datos actuales del formulario sin guardar.
- [ ] Preview muestra `VISTA PREVIA · SIN VALIDEZ`.
- [ ] Preview no crea diploma, código ni histórico.
- [ ] Auditoría registra validaciones, incidencias, reservas, cambios de cuota y configuración de WhatsApp.
- [ ] Auditoría no expone contraseñas, tokens o contenidos base64.

## Gate 7 · Persistencia

Después de realizar cambios de QA:

- [ ] Recargar navegador conserva los datos esperados.
- [ ] Reiniciar/redeploy del servicio conserva los datos del volumen.
- [ ] Los contextos de trabajo de administradores no se convierten en selección global después del reinicio.

## Cierre

Solo preparar merge a `main` cuando todos los gates críticos estén en PASS. Cualquier mejora nueva no crítica detectada durante esta QA pasa a V1.2. Los bugs P1/P2 encontrados durante QA sí se corrigen antes del merge.
